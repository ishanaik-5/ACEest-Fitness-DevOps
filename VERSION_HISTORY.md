
# ACEest Fitness & Gym — Application Version History

## 1. Introduction

This document maintains the version history of the ACEest Fitness & Gym application for DevOps Assignment 2.

The application versions supplied with the assignment are retained as reference implementations to understand the evolution of the fitness and gym management system.

The existing Flask application developed in Assignment 1 is continued as the primary application codebase. The supplied Python versions are used to study functionality and guide further enhancements to the Flask application.

## 3. Primary Functional Reference

Version 3.2.4 is selected as the primary functional reference for Assignment 2 because it is the latest version supplied with the assignment.

The relevant functionality are implemented in the Flask application using its existing architecture, routes, templates and database implementation.

## 4. Assignment 1 Application Continuity

The Flask application developed in Assignment 1 remains the main application codebase.

The supplied Python versions are maintained separately under the `legacy_versions/` directory for reference and version-history purposes.

The original Flask application file `app.py` is retained and will not be overwritten by the supplied reference files.

## 5. Assignment 2 Development Approach

The following development approach followed:

1. Review the supplied application versions.
2. Use version 3.2.4 as the primary functional reference.
3. Compare its functionality with the existing Flask application.
4. Identify relevant missing functionality and improvements.
5. Implement required changes in the Flask application.
6. Validate changes using Pytest.
7. Track application and infrastructure changes using Git commits, branches and version tags.
8. Integrate the application with Docker, Jenkins, SonarQube and Kubernetes.

## 6. Version Control and Maintenance

All supplied reference files are preserved without modifying their original contents.

New application features, bug fixes and DevOps infrastructure changes will be tracked through structured Git commits and version tags.
